# contract-first: 불신을 기본값으로 삼는 설계

외부 입력도 모델 출력도 미래의 자기 자신도 일단 의심한다. 신뢰는 검증으로 확보한다.
이 스킬은 기계가 구문만으로 판정하지 못하는 설계 규율층이며 `finish-the-work`(철학 5, 테스트까지가 완료)와 함께 작동한다.

## 적용 시점

새 코드를 작성하거나 기존 코드를 수정할 때, 특히 신뢰 경계를 넘는 데이터(사용자 입력, API 및 모델 응답, 파일, 환경변수, 시스템 시계)를 다룰 때 적용한다.

## 수행 절차

1. **경계에서 불신한다**: 신뢰 경계(외부에서 내부로 들어오는 지점)를 식별하고 해당 입력을 신뢰할 수 없는 값으로 간주한다. "이 값이 잘못되었거나 조작되었다면 어떻게 되는가?"를 먼저 확인한다.

2. **의미값을 재조립한다**: 의미가 중요한 값은 외부나 모델이 전달한 값을 그대로 쓰지 않고 권위 소스로 재구성한다.
   - 모델이 생성한 날짜 대신 시스템 시계를 사용한다. ID, 해시, 타임스탬프, 순번은 코드가 직접 생성한다. 모델 출력에서는 **판단**​만 취하고 **사실**​은 엔진이 생성한다.

3. **범위 제한 및 매핑을 수행한다** (`clamp`): 수치와 열거형은 유효 범위 안으로 강제한다.
   - 수치: `max(lo, min(hi, x))`. 열거형: 허용 목록(allowlist) 매핑을 적용하고 미지 값은 안전 기본값으로 치환하거나 명시적으로 거부한다.

4. **경계값 4종으로 테스트를 구성한다**: 각 입력 계약마다 최소 네 가지 경계를 검증한다.
   - **정상**(happy) · **매핑**(경계, 변환, 범위 끝) · **누락**(빈 값, `None`, `null`) · **변조**(형식 오류, 범위 초과, 악의적 입력)

5. **계약을 명시적으로 기록한다**: 함수와 모듈의 입력 가정(타입, 범위, `null` 허용 여부, 실패 시 동작)을 주석이나 독스트링에 기재한다. 중요한 설계 선택이면 `horos decide D<n> <why> <cost> <escape>` 명령으로 원장에 외화하고 코드 주석(`# D<n>`)으로 참조한다.

6. **검증 가능한 주장을 남긴다** (감사층): 신뢰 경계를 다루는 변경을 마쳤으면 무엇을 수행했고 어떤 조건이 참인지 `horos claim` 명령으로 기록한다. `claim-guard` 엔진은 **의미 진리가 아니라** 주장의 형식, 해시 바인딩 신선도, 내부 불변식, 원장 교차참조를 결정론적으로 판정한다. 예: `horos claim completion "입력 검증 및 경계값 4종 추가" "parse.py,tests/test_parse.py" "" "tests_added"`.

## 완료 전 체크리스트

- [ ] 외부 및 모델 입력에 검증과 정규화를 적용했는가?
- [ ] 수치와 열거형을 유효 범위로 제한(clamp)하거나 매핑했는가?
- [ ] 날짜, ID, 해시 등 의미값을 권위 소스로 재조립했는가?
- [ ] 경계값 4종(정상, 매핑, 누락, 변조) 테스트를 작성했는가?
- [ ] 입력 계약을 주석이나 독스트링에 명시했는가?
- [ ] 변경 내역을 덮는 검증 가능한 주장을 `horos claim`으로 기록했는가?

## 금지 패턴

- 모델이나 외부 입력값을 검증 없이 신뢰 경계 안으로 반입하는 행위.
- 정상 경로(happy path) 테스트만 작성하고 누락·변조 케이스를 생략하는 행위.
- 상하한 범위가 없는 수치를 제한(clamp) 없이 그대로 사용하는 행위.
- "이번에는 괜찮겠지"라고 가정하는 행위: 미래의 자기 자신도 검증 대상이다.
